# A2A 协议

Supervisor 与五个领域 Agent 通过统一、版本化的消息合同通信。协议负责“任务怎样交付和追踪”，领域工具负责“业务怎样读取或写入”，两者边界独立。

## 消息与结果

任务消息包含 `message_id`、`schema_version`、运行与会话标识、目标能力、参数、依赖和重试信息。领域 Agent 返回统一 Result，记录状态、业务载荷、错误类型、证据引用和 trace 关联信息。

运行时只派发已注册能力。消息版本、参数合同或绑定不合法时，任务会在调用工具之前失败，避免把协议错误伪装成业务拒绝。

## 调度语义

- **依赖等待**：节点只在所有上游任务成功并完成参数绑定后进入可运行状态。
- **并行执行**：没有依赖关系的节点可以独立派发。例如读取订单后，物流查询与售后资格判断可以并行。
- **幂等去重**：重复投递复用已记录结果，不重复产生业务副作用。
- **有界重试**：仅对声明为可重试的瞬时失败重试，并受最大次数约束。
- **迟到隔离**：超过当前运行生命周期的消息不能改变已经完成的终态。
- **失败传播**：上游失败会按计划策略阻断依赖节点，结果中保留原始错误类别。

## 可追踪性

每次运行通过 Run → Plan → Task → Tool → Result 链路关联。ledger 保存消息状态迁移，trace 保存调用和结果证据；事件序号单调递增，payload hash 用于识别内容是否被修改。

## 五领域能力

| Agent | 主要能力 | 输入来源 |
|---|---|---|
| Product | 商品目录查询 | SKU、商品描述 |
| Order | 订单读取与归属校验 | 订单号、会话身份 |
| Logistics | 物流轨迹查询 | 运单号，或订单结果派生字段 |
| Policy | 政策与知识检索 | 原始问题、时间与范围 |
| AfterSales | 售后读取、资格判断、受控写 | 订单结果、服务类型、确认令牌 |

协议相关实现位于 `agent/r4_a2a_contracts.py`、`agent/r4_a2a_runtime.py` 与 `agent/r5_a2a_runtime.py`。
